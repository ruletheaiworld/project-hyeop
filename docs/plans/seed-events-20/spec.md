# spec — seed-events-20

## 목표
`eventEditor/data.json` 에 합리적 분포의 이벤트 카드 20장을 추가해, 게임 엔진 구현 전이라도 편집기에서 카탈로그가 어떻게 보이는지 시뮬레이션 가능하게 만든다. 추후 엔진 작업의 초기 시드 데이터로도 그대로 사용된다.

## 범위

- 포함:
  - `data.json` 에 새 카드 20장 추가 (모두 `활성상태: on`)
  - 카드 포맷은 `direction.md` 3-3 / 3-4 준수
  - id 명명은 `direction.md` 3-4-1 의 수동 규칙 사용 (`지역_장소_주제`)
  - 표기는 `dictionary.md` SSOT 준수 (체력 / 내공 / 무예 / 학식 / 명성 / 도덕 / 은자)
  - 선택지 결과 표기는 `system.md` §9 의 파싱 가능 형식 사용
  - 지역 3종(청운현 / 흑풍산 / 낙양성) 모두 커버, 타입 4종(프롤로그 / 일반이벤트 / 전투이벤트 / 엔딩이벤트) 분포

- 제외:
  - 기존 비활성 카드 2장 (`ev_mpxgr2nm_t4qvf`, `ev_mpzidm0v_i0s0j`) **절대 수정·삭제 금지**. id·이름·상태 모두 그대로 유지
  - `setting.md` 의 문파·인물·아이템 카탈로그 채우기 (이번 작업은 이벤트만)
  - 엔진 동작 검증 (엔진 미구현)
  - 밸런싱 (가중치·능력치 변동량은 거친 초안. 추후 조정)

## 완료 조건 (Definition of Done)

- [ ] `data.json` 총 카드 수 = 기존 2 + 신규 20 = **22**
- [ ] 신규 20장 모두 `활성상태: on`
- [ ] 기존 2장 (`[보관]…` prefix) 그대로 보존됨 (id·이름·상태 변경 없음)
- [ ] 각 신규 카드의 id 가 유일 (충돌 없음)
- [ ] 표기 위반(체력·내공·무예·학식·명성·도덕·은자 외 표기) 없음
- [ ] 편집기 (`http://localhost:3700`) 강제 새로고침 후 22장 모두 정상 표시
- [ ] `후속이벤트` 참조가 깨지지 않음 (참조하는 id 가 실제 카탈로그에 존재)

### 분포 계획 (초안)

| 항목 | 분포 |
|---|---|
| 지역 | 청운현 8 / 흑풍산 7 / 낙양성 5 |
| 타입 | 일반이벤트 14 / 전투이벤트 4 / 엔딩이벤트 2 |
| 가중치 | 0(후속 전용) 4 / 1~3 6 / 4~6 7 / 7~10 3 |
| 후속 체인 | 최소 3쌍 (일반→전투, 일반→엔딩, 일반→일반) |

### 결과 표기 어휘 (system.md §9 발췌)

- 능력치 변동: `체력 +1`, `은자 -2`, `도덕 +1, 명성 -1`
- 상태값 획득: `상태값: 인연(노인) 획득`, `상태값: 부상 = 경상`
- 트리거: `전투 발생`, `엔딩 — 객사`

## 비고

- **NPC / 문파명**: 카드 안에서 이름 있는 NPC(예: `노인`) 나 문파(예: `흑풍채`) 를 등장시키면, 추후 `setting.md` 에 카드로 추가될 예정. 이번 작업에선 setting.md 갱신은 안 함 — 그러나 일관성을 위해 새로 도입하는 명칭은 최소화하고 `direction.md` 5장의 지역 키워드(객잔·의원·표국·뒷골목 / 산적·기연·동굴·은거고수 / 문파·비무대회·정보상·권력 암투)를 따른다.
- **마교 노선**: `main.md` 의 "마교 vs 정파 양 수장 사망" 도입부 + 출신 `낭인` 시작과 자연 합치하도록, 마교 카드는 *소문/풍문* 수준으로만 등장시키고 입문 경로는 박지 않는다 (`'마교 타락'` 엔딩 게이트 재설계가 펜딩이므로).
- **밸런싱**: 능력치 변동 폭은 ±1 ~ ±3 범위로 유지. 극단값(예: `명성 +10`)은 엔딩 카드에만 한정.
- **가중치 0**: 4장 — 후속 전용. 전투 후속 2장, 엔딩 도달 후속 2장 분포.
- **수정 방식**: `data.json` 을 `Edit` 도구로 직접 갱신 (서버에 POST 보낼 필요 없음 — 강제 새로고침이면 충분).
