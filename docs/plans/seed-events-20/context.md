# context — seed-events-20

## 사용자의 원 요청

> 지금 내가 추가해둔 건 일단 비활성화 해뒀거든? 이건 절대 삭제하지말고 니가 알아서 임의의 이벤트 20개 만들어줘.

(같은 메시지에서 `/plan-memory` 호출 → `ai-plan-memory` 스킬로 실행)

## 왜 이걸 지금 하는가

- 현재 `data.json` 에 카드 2장만 있고 둘 다 비활성 (`[보관]` prefix). 즉 **편집기로 보면 사실상 빈 상태**.
- 게임 기획 문서(`direction.md`, `system.md`, `dictionary.md`) 와 SSOT 패턴은 굳었지만, 카탈로그가 비어 있어서 *추상 → 실체* 의 첫 단계가 막혀 있음.
- 시드 카드 20장을 박으면:
  1. 편집기 UX 가 카드 다수일 때 어떻게 보이는지 확인 가능 (목록·필터·툴팁·가중치 바 등)
  2. 추후 엔진 작업 시 즉시 시뮬레이션 가능한 초기 데이터 보유
  3. `setting.md` 의 문파·인물·아이템 카탈로그가 어떤 카드를 필요로 하는지 역추산 가능 (이벤트에 등장하는 명칭이 후속 카탈로그 시드가 됨)

## 결정된 방향

비활성 2장은 **그대로 두고**, 신규 20장을 활성 상태(`on`)로 추가. `direction.md` 3장의 카드 포맷·id 명명 규칙·표기 SSOT 를 엄격히 준수. 분포·내용은 AI 위임.

## 기각된 대안

- **비활성 2장 활성화 후 보강** — 사용자가 "[보관]" prefix 로 명시적 비활성을 선언했고 "절대 삭제 금지" 라는 강한 제약. 의도된 비활성으로 판단해 손대지 않음.
- **외부 LLM 으로 20장 일괄 생성** — 데이터 일관성 위험(표기·id 규칙·결과 어휘 일탈). 사용자 "니가 알아서" 톤도 *내가 직접 작성* 을 의미.
- **`setting.md` 카탈로그부터 먼저 채우기** — 카탈로그 → 이벤트 순서가 정석이지만, 카탈로그가 빈 채로 이벤트 작성하면 *이벤트에서 등장하는 명칭이 카탈로그를 역으로 끌고 옴*. 시간 절약. 추후 setting.md 작업이 자연스럽게 시드 갖춤.
- **데이터를 서버 POST 로 입력** — `Edit` 직접이 더 단순. 결과 동일.

## 제약 / 합의 사항

- 기술적 제약:
  - 기존 비활성 카드 2장 `id`·`이벤트명`·`활성상태` 모두 보존
  - 표기는 `dictionary.md` SSOT (체력·내공·무예·학식·명성·도덕·은자) — 위반 시 작업 무효
  - id 명명: `direction.md` 3-4-1 수동 규칙 (`지역_장소_주제` snake_case)
  - 결과 표기는 `system.md` §9 어휘 안에서만
- 시간·범위 제약:
  - 한 세션에 끝낼 분량 (20장)
  - 밸런싱은 추후 — 이번엔 합리적 초안 수준
- 사용자가 명시한 선호:
  - 비활성 2장 절대 보호 (반복 명시할 만큼 중요)
  - 분포·내용은 AI 위임 ("니가 알아서")
