# context — terminology-dictionary

## 사용자의 원 요청

> "docs의 concept밑에 dictionary.md 추가해줘. 거기에는 용어 통일을 시킬거야.
>  일단 추가할건 hp/체력 → 체력, 내공/내력 → 내공, 무공/무력/무예 → 무예, 학력/지식/지혜
>  → 학식, 명성/명예/인기 → 명성, 심성/착함/나쁨 → 도덕, 돈/은자/은냥/동냥 → 은자.
>  이거 일단 정리해줘."

## 왜 이걸 지금 하는가

기존 기획 문서 작성 과정에서 동일 개념을 가리키는 표기가 분기되어 있었다.

- `direction.md` 본문 — `무공` 과 `무예` 가 한 문단 안에서도 혼용됨, `은전` 으로 표기
- `direction.md` 능력치 표 — `무예` 로 표기, `은자` 로 표기
- `system.md` — 영문 키 `martial` / `money` 로 정리되어 있고, 주석에서 `무예` / `은자` 선택
  ("나는 이 시점에서 무예/은자로 통일하기로 선택" 류의 메모)
- 이벤트 카드(`events.md`, eventEditor) — 본문 텍스트 안에서 표기 자유 변동 가능성 있음

문서가 더 늘어나기 전에, 그리고 카드 본문을 진지하게 채우기 전에 SSOT 한 군데를
박지 않으면 추후 일괄 치환 비용이 빠르게 커진다. 이번 1차는 능력치 7종만 끊는다.

## 결정된 방향

`docs/concept/dictionary.md` 한 파일을 **표기 SSOT** 로 만들고, 다른 모든 문서는 이 파일을
참조한다. 1차 범위는 능력치 7종.

## 기각된 대안

- **각 문서 안에서 일관성만 맞추고 별도 사전 없이 가기** — 기각. 문서가 늘어날 때마다
  매번 모든 문서를 다시 읽어 표기를 맞춰야 함. SSOT 가 없으면 결국 표류함.
- **direction.md 안에 용어 표를 두기** — 기각. direction.md 는 "방향성·의견" 이 책임이라
  성격이 다름. 사전은 사전대로 분리해야 다른 문서에서도 동등하게 참조 가능.
- **system.md 의 영문 키만으로 충분하다고 보기** — 기각. system.md 는 코드 친화적 스키마
  중심. 한글 표기 정리가 빠지면 본문·이벤트 카드의 자연어 표기가 여전히 표류.

## 제약 / 합의 사항

- 기술적 제약:
  - 영문 키는 `system.md` 와 **반드시 일치**. 변경이 필요하면 system.md 부터 손대고
    사전이 따라간다.
- 시간·범위 제약:
  - 1차는 능력치 7종까지. 상태값·지역·이벤트 타입은 별도 작업.
- 사용자가 명시한 선호:
  - 통일 규칙은 사용자 지정 그대로 (체력/내공/무예/학식/명성/도덕/은자)
  - "정리해줘" — 즉시 1차 작업 진행 OK
